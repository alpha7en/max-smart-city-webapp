# Памятка редактору текстов бота ЖКХ

Все тексты сообщений и кнопок бота собраны в этой папке в формате YAML. Вы можете редактировать их прямо через веб-интерфейс GitHub (кнопка ✏️ «Edit file» в правом верхнем углу любого файла).

---

## 📁 Структура файлов по сценариям

| Файл | Что внутри |
|---|---|
| [`common.yaml`](common.yaml) | Приветствие, ошибки, базовые кнопки («Назад», «В меню», «Отмена»). |
| [`registration.yaml`](registration.yaml) | Шаги регистрации: ввод ФИО, телефона, адреса, номера квартиры, ошибки валидации. |
| [`submission.yaml`](submission.yaml) | Главный сценарий подачи показаний: фото, распознавание, ручной ввод, выбор счётчика, экран проверки. |
| [`menu.yaml`](menu.yaml) | Главное меню, дашборд, кнопки меню, заглушки поверки и оплаты. |

| [`profile.yaml`](profile.yaml) | Экран профиля пользователя, редактирование телефона/адреса, права доступа. |
| [`invite.yaml`](invite.yaml) | Гостевой доступ: инвайт-ссылки, приглашение жильцов собственником. |
| [`notify.yaml`](notify.yaml) | Напоминания и уведомления: о сроке подачи, поверке, счетах. |

| [`api.yaml`](api.yaml) | Сообщения об ошибках для мини-приложения и системные ответы. |
| [`hackathon_demo.yaml`](hackathon_demo.yaml) | Только для хакатона: предложение сгенерировать демо-профиль после регистрации. |

## ⚠️ Важные правила редактирования

### 1. Переменные в фигурных скобках `{...}`
Текст содержит динамические подстановки (плейсхолдеры):
* `{name}` — имя пользователя (например, *Анна* или *Иванова Анна Сергеевна*)
* `{date}` / `{deadline}` — даты (например, *25 октября*, *15.03.2030*)
* `{amount}` — сумма счёта (например, *4 312 ₽*)
* `{meter}` / `{label}` — название счётчика или адреса
* `{value}` — числовое показание (например, *123,456 м³*)

> **Критично:** Не удаляйте и не переименовывайте переменные (например, нельзя заменять `{name}` на `{имя}`), иначе бот не сможет отправить сообщение. Менять слова вокруг переменной можно свободно.

---

### 2. Ограничения длины кнопок MAX
Мессенджер MAX строго ограничивает ширину кнопок на экранах смартфонов:
* **Обычные кнопки (`BTN_*`)**: не длиннее **24 символов**.
* **Срочные кнопки (`URGENT_*`)**: не длиннее **32 символов**.
* **Варианты счётчиков и адресов**: не длиннее **40 символов**.

*Если подпись будет длиннее, мессенджер либо не отобразит клавиатуру вовсе, либо некрасиво обрежет текст троеточием.*

---

### 3. Длина сообщений и Tone of Voice
* **Стиль**: от лица сервиса пишем «мы», к пользователю обращаемся на «вы» (со строчной буквы).
* **Краткость**: не более **8 строк** в одном сообщении. Пользователь в чат-боте должен сразу видеть суть и кнопку действия.
* **Без канцелярита**: избегайте слов *«данный»*, *«успешно»*, *«осуществляется»*, *«в целях»*.
* **Без графических эмодзи**: эмодзи запрещены дизайн-системой бота.
* **Без CAPS LOCK**: не пишите капсом (единственное разрешённое исключение: *«ПРИШЛИТЕ ВАШЕ ФОТО В ЧАТ»*).

---

### 4. Разметка текста (Markdown)
* **Жирный шрифт**: `**важный текст**` (выделяем показания, суммы, даты окончания срока).
* **Сноски и оговорки о демо-данных**: блок цитаты `> Текст сноски`.
* **Сырые ссылки**: не вставляйте ссылки прямо в текст сообщений (только через специальные кнопки-ссылки).

---

## 🛠 Автоматическая проверка
После сохранения изменений в репозитории запускается тест целостности текстов:
```bash
pytest tests/test_texts_integrity.py
```
Он автоматически проверит, что:
1. Синтаксис YAML не нарушен.
2. Все необходимые переменные `{...}` на месте.
3. Кнопки не превышают лимиты по символам.
4. В текстах нет случайных эмодзи.
