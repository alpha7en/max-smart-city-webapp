# Единый бот ЖКХ в MAX

Чат-бот и мини-приложение для мессенджера MAX (хакатон «Умный город», трек «Умный дом / ЖКХ»). Житель один раз
регистрируется, а дальше подаёт показания счётчиков фотографией: присылает снимок в чат, бот распознаёт цифры
и заводской номер, показывает их на проверку и записывает. Бот напоминает о сроках подачи, поверки и оплаты,
проверяет поверку счётчика в реестре Росстандарта, а собственник может открыть доступ к квартире семье или арендатору.

- **Бот:** [max.ru/t226_hakaton_max_bot](https://max.ru/t226_hakaton_max_bot) или поиск `t226_hakaton_max_bot` в MAX.
- **Мини-приложение:** кнопка «Мини-приложение» в меню бота (размещено на `https://maxsmartcity.ru`).

## Что умеет

- **Регистрация** в три шага: ФИО, телефон (кнопкой «Отправить мой номер» или текстом), адрес.
  Адрес проверяется по ФИАС через DaData.
- **Подача по фото.** Фото можно прислать в любой момент, даже до регистрации. Бот спрашивает, какой это счётчик,
  распознаёт показание и серийный номер, показывает экран проверки («Отправить», «Исправить», «Переснять»).
  Не распознал — называет причину (блик, размыто, нет цифр) и предлагает переснять или ввести вручную.
- **Проверки показания:** формат, «меньше прошлого», слишком большой прирост, повторная подача за месяц.
- **Серийный номер** обязателен: сверяется с сохранённым, проверяется по типу счётчика.
- **Поверка по ФГИС «Аршин»**: после первой подачи с номером бот находит запись о поверке в реестре
  Росстандарта; нет записи — спрашивает дату из паспорта.
- **Меню-дашборд**: что подано за месяц, срок подачи, счёт, ближайшая поверка; самое срочное — первой кнопкой.
- **Уведомления**: открылось окно подачи и последние дни, поверка через 30/7/1 день и просрочка, счёт за 5/1 день.
- **Права по адресу**: первый зарегистрированный — собственник, следующие просят у него доступ.
- **«Поделиться доступом»**: одноразовая ссылка на один или несколько адресов, «Общий доступ», закрыть доступ, выйти.
- **Мини-приложение**: главная с дашбордом, подача по фото или вручную, история счётчика, профиль, общий доступ.

## Как проверить

Готовый бот работает на сервере, ничего запускать не нужно. Работает в мобильном приложении MAX и в веб-версии.

| # | Действие в MAX | Что должно произойти |
|---|---|---|
| 1 | Открыть бота по ссылке выше, нажать «Начать» или написать «привет» | приветствие и вопрос ФИО |
| 2 | ФИО, телефон («Отправить мой номер» или текстом), адрес | сводка и кнопка «Всё верно» → меню-дашборд с демо-счётом |
| 3 | Прислать фото счётчика, выбрать тип и адрес (у нового профиля счётчиков нет — бот сразу спросит тип) | «Смотрим на фото…», экран проверки с распознанным показанием |
| 4 | Если номер на фото не виден — «Ввести номер» (например, `18-452178`), затем «Отправить» | «Готово! Записали …», срок поверки из ФГИС или вопрос о дате из паспорта |
| 5 | Ещё раз фото того же счётчика и «Отправить» | «За <месяц> уже передано… Заменить на …?» |
| 6 | `/demo` → «О поверке», «О счёте» | уведомления с рабочими кнопками |
| 7 | «Мини-приложение» в меню | главная, подача по фото, история счётчика, профиль |
| 8 | «Профиль» → «Поделиться доступом», открыть ссылку со второго аккаунта MAX | второй аккаунт получает доступ к адресу, первый — сообщение об этом |
| 9 | «Профиль» → «Удалить мои данные» → «Удалить» | данные удалены, следующее сообщение — снова регистрация |

Быстрый путь без регистрации — команда `/demo_profile` (до регистрации; если профиль уже есть, сначала
«Удалить мои данные»): бот создаст вымышленный профиль с двумя адресами, счётчиками, историей показаний
за полгода и общим доступом. Если адрес из шага 2 уже зарегистрировал другой проверяющий, при подаче бот ответит
«уже зарегистрирован собственник» — нажмите «Открыть доступ (демо)». Полный пример переписки —
[docs/dialog-example.md](docs/dialog-example.md).

Отдельного публичного API у решения нет: `/api/*` — внутренний бэкенд мини-приложения, он принимает только
подписанный MAX `initData` ([описание](docs/api.md)). Доступность сервера: `curl https://maxsmartcity.ru/api/health` → `{"ok":true}`.

## Интеграции

Все интеграции настоящие. Запасной вариант нужен на случай, когда ключ не задан (например, при локальном
запуске) или сервис недоступен: бот не падает, а продолжает работу и помечает это в сообщении.

| Сервис | Что даёт | Настройка | Запасной вариант |
|---|---|---|---|
| MAX Bot API и мини-приложения | сообщения, кнопки, фото, контакт, авторизация мини-приложения по initData | `BOT_TOKEN` | — |
| Yandex Cloud AI Studio (Qwen) через сервис `recognizer` | показание, тип счётчика, заводской номер, марка и модель по фото | `YC_API_KEY`, `YC_FOLDER_ID` | демо-распознавание с пометкой — для локального запуска без ключей |
| DaData | подсказки и проверка адреса по ФИАС | `DADATA_API_KEY` | локальный разбор строки, пометка «не сверен с ФИАС» |
| ФГИС «Аршин» (Росстандарт) | срок поверки по заводскому номеру из реестра | `ARSHIN_MODE=live` (по умолчанию) | `fixtures` — демо-данные без сети, `off` — выключено |

Качество распознавания измерено на водомерах (датасет Yandex.Toloka, 373 фото вне подбора промпта): 74% показаний
точно, 91% верных целых м³, около 2,7 с на фото ([методика](services/recognizer/README.md#качество)).
Электричество, газ и тепло модель тоже читает, но на датасетах их ещё не мерили, поэтому бот просит
внимательно проверить цифры.

## Что смоделировано

Эти части MVP работают на модели вместо внешних систем; в сообщениях бота и в мини-приложении это помечено.

| Что | Как сейчас | Что нужно для реальной работы |
|---|---|---|
| Передача показаний в УК | показание хранится у нас, пометка «передача в УК смоделирована» | API УК, РСО или ГИС ЖКХ |
| Окно подачи | с 15 по 25 число для всех адресов (`SUBMIT_DAY_FROM/TO`) | график УК по адресу |
| Счета | один демо-счёт на адрес за прошлый месяц, оплатить до 10-го | начисления из биллинга |
| Оплата и запись на поверку | заглушки «появится скоро» | платёжный сервис, сервис записи |
| Права собственника | первый зарегистрированный по адресу — собственник | данные УК или ЕГРН |

## Запуск

Локальный запуск воспроизводит сборку; для проверки в MAX удобнее готовый бот (раздел выше).

1. **Склонировать репозиторий и создать `.env`:**
   ```bash
   git clone https://github.com/alpha7en/max-smart-city-webapp.git && cd max-smart-city-webapp
   cp .env.example .env
   ```
2. **Вписать ключи в `.env`** (все переменные описаны в самом файле):
   - `BOT_TOKEN` — токен бота MAX. Без него поднимутся только API и мини-приложение.
     **Не используйте токен прод-бота:** два процесса с одним токеном делят между собой сообщения MAX.
   - `YC_API_KEY`, `YC_FOLDER_ID` — Yandex Cloud, сервисный аккаунт с ролью `ai.languageModels.user`
     (без них — демо-распознавание).
   - `DADATA_API_KEY` — ключ DaData (без него — локальный разбор адреса).
3. **Собрать и запустить:**
   ```bash
   docker compose up -d --build
   ```
   Поднимутся контейнеры `app` (бот, API, мини-приложение, порт 8080) и `recognizer` (распознавание,
   порт 8000 только на `127.0.0.1`). Compose сам передаст боту адрес `recognizer`.
4. **Проверить:**
   ```bash
   curl -s localhost:8080/api/health     # {"ok":true}
   curl -s localhost:8000/health         # {"status":"ok",…} — сервис распознавания
   docker compose logs -f app            # «MAX bot: id=… username=…» и «polling started»
   ```
   Без `BOT_TOKEN` в логе будет `BOT_TOKEN is not set — bot is disabled`: это ожидаемо.
5. **Открыть своего бота в MAX** и пройти сценарий из раздела «Как проверить».

Остановка и сброс:

```bash
docker compose down           # остановить; данные в ./data сохраняются
sudo rm -rf data              # полный сброс (после down; файлы принадлежат пользователю контейнера, uid 10001)
```

**Без Docker** (Python 3.12):

```bash
python3.12 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
uvicorn app.main:app --env-file .env --port 8080
```

**Мини-приложение локально:** `DEV_AUTH=true` в `.env`, затем `http://localhost:8080/app/?dev_user=<MAX user_id>`.
Внутри MAX мини-приложение открывается только с HTTPS-домена ([прод](docs/deploy.md)).

## Окружение

- **Docker Engine с Compose v2.24+**, образы на `python:3.12-slim`. Без Docker — Python 3.12.
- **Порты:** `8080` — `app` (API, статика мини-приложения на `/app/`, `/` перенаправляет туда);
  `8000` — `recognizer`, на хост только `127.0.0.1`. Входящих подключений от MAX боту не нужно.
- **Исходящие HTTPS-соединения:** `platform-api2.max.ru` и CDN MAX (фото), `llm.api.cloud.yandex.net`
  (из `recognizer`), `suggestions.dadata.ru`, `fgis.gost.ru`.
- **Сеть:** ФГИС «Аршин» отвечает только российским IP; MAX Bot API из-за рубежа тоже может быть недоступен.
  TLS проверяется всегда, сертификаты Минцифры для MAX лежат в [`certs/`](certs/README.md).
- **Мини-приложению** в MAX нужен постоянный HTTPS-домен; на проде его и API отдаёт nginx ([docs/deploy.md](docs/deploy.md)).

## Переменные окружения

Все переменные бота читает `app/config.py`; `.env.example` — шаблон с комментариями.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота MAX. Пусто — бот и уведомления выключены, работают API и мини-приложение | — |
| `BOT_USERNAME` | username бота для кнопки мини-приложения | из `GET /me` |
| `MAX_API_BASE` | адрес Bot API | `https://platform-api2.max.ru` |
| `DADATA_API_KEY` | подсказки адресов DaData. Пусто — локальный разбор | — |
| `RECOGNIZER_URL` | адрес сервиса распознавания; в compose при заданном `YC_API_KEY` подставляется сам. Пусто и без ключей — демо-распознавание | — |
| `ARSHIN_MODE` | ФГИС «Аршин»: `live` — реестр, `fixtures` — демо-данные без сети, `off` — выключено | `live` |
| `ARSHIN_BASE` | адрес API ФГИС | `https://fgis.gost.ru/fundmetrology/eapi` |
| `ARSHIN_FALLBACK_IPS` | IP хоста ФГИС через запятую, если DNS в контейнере его не находит. Пусто — выключено | `212.164.138.19,212.164.138.14` |
| `DEMO_MODE` | `/demo` с примерами уведомлений и кнопка «Открыть доступ (демо)» | `true` |
| `HACKATHON_DEMO_PROFILE` | команда `/demo_profile` (только для хакатона) | `true` |
| `DEV_AUTH` | заголовок `X-Dev-User` вместо initData, только для локальной разработки | `false` |
| `INIT_DATA_TTL` | срок действия initData мини-приложения, секунды | `86400` |
| `MINIAPP_ORIGINS` | CORS: домены мини-приложения, если оно открыто не с домена API | — |
| `DATA_DIR` | каталог SQLite и временных фото | `data` |
| `TZ` | часовой пояс сроков и уведомлений | `Europe/Moscow` |
| `SUBMIT_DAY_FROM`, `SUBMIT_DAY_TO` | окно подачи, числа месяца | `15`, `25` |

Переменные контейнера `recognizer` (из того же `.env`): `YC_API_KEY`, `YC_FOLDER_ID`, `YC_MODEL`
(`qwen3.6-35b-a3b`), `YC_TIMEOUT` (`15` с). `MAX_TEST_USER_ID` читает только `tools/live_smoke.py`.

Бот сам забирает обновления из MAX (long polling), входящих подключений к нему нет. Мини-приложение
и его API отдаёт nginx с одного домена. Синим выделены наши сервисы; во внешние сервисы ходят только они.

Один процесс FastAPI: long polling MAX, роутер и сценарии бота, планировщик уведомлений и API мини-приложения.
Бизнес-логика общая для бота и API: подача (`app/readings.py`), дашборд (`app/domain/dashboard.py`),
общий доступ (`app/sharing.py`). Подробно — [docs/architecture.md](docs/architecture.md).

```
app/
  main.py            FastAPI: /api/*, статика /app/, в lifespan — poller и scheduler
  config.py clock.py настройки из окружения; время МСК (в тестах подменяется)
  db.py schema.sql   SQLite (WAL), миграции по PRAGMA user_version
  repo.py            весь SQL
  readings.py        подача показания: проверки и запись
  sharing.py         «Поделиться доступом»
  verification.py    поверка по ФГИС «Аршин»
  scheduler.py       уведомления, чистка фото, суточное обновление поверки
  domain/            чистые функции: счётчики, адреса, люди, права, серийные номера, поверка, дашборд
  integrations/      внешний HTTP: MAX, распознавание, DaData, ФГИС
  bot/               события, роутер, сессии, кнопки; flows/ — сценарии; texts/ — все тексты (YAML)
  web/               авторизация initData, /api/*, static/ — мини-приложение (vanilla JS)
services/recognizer/ сервис распознавания: фото → Qwen в Yandex Cloud → показание и номер
tests/               pytest: сценарии через настоящий роутер и FakeMaxApi
tools/               live_smoke.py — живая проверка MAX API; transcript.py — пример диалога; architecture_svg.py — схема
```

## Данные

**Что собираем.** ФИО, телефон и адрес при регистрации, фото и показания счётчиков, заводские номера.
Перед вводом ФИО бот предупреждает: «Продолжая, вы соглашаетесь на обработку персональных данных».
Данные передаются только по HTTPS.

**Где храним.** SQLite на нашем сервере (том `./data`). Фото — временные файлы: удаляются после подачи,
отмены или по сроку (30 минут; фото, присланное до регистрации, — 24 часа). Фото из мини-приложения удаляется
сразу после распознавания.

**Кому передаём.** Фото — в Yandex Cloud AI Studio на время распознавания; текст адреса — в DaData;
заводской номер счётчика — в публичный реестр ФГИС «Аршин». ФИО и телефон никуда не уходят. Телефон видит только
собственник адреса в запросе доступа, другим жильцам показывается «Имя Ф.».

**Удаление.** «Профиль» → «Удалить мои данные» удаляет профиль, связи с адресами, сессию, фото и историю
уведомлений. Показания и счётчики остаются за адресом, но без привязки к человеку; права собственника
переходят к первому, кому он открыл доступ.

**Секреты** — только в `.env` (он в `.gitignore`); `tests/test_security.py` проверяет, что ключей и `verify=False`
в репозитории нет. Версии зависимостей зафиксированы.

**Тестовые и сгенерированные данные** — все синтетические и помечены прямо в боте:

| Данные | Откуда | Пометка |
|---|---|---|
| Профиль `/demo_profile` | генерирует код: случайные ФИО и телефоны, реальные дома со случайной квартирой, показания за полгода, демо-жильцы без аккаунта MAX | команда только для хакатона |
| Демо-счета | по одному на адрес, сумма зависит от id адреса | «Счёт демонстрационный» |
| `/demo` | примеры уведомлений; «О поверке» ставит модельный срок поверки | «смоделирована для демо» |
| `ARSHIN_MODE=fixtures` | записи ФГИС из `app/integrations/arshin_demo.json` | «Данные ФГИС «Аршин» демонстрационные» |
| Демо-распознавание | без ключей Yandex Cloud: прошлое показание + прирост | «Демо-распознавание» |
| [docs/dialog-example.md](docs/dialog-example.md), тесты | вымышленные люди и адреса | — |

`tests/fixtures/arshin/` — настоящие ответы публичного реестра ФГИС по заводским номерам счётчиков,
персональных данных в них нет.

## Известные ограничения

- **Обновления MAX бот получает через long polling**, а для боевого решения MAX требует webhook.
  Переход (подписка `POST /subscriptions` и приём апдейтов в `app`) пока не сделан. С одним токеном
  должен работать один процесс, иначе апдейты делятся между ними.
- **Распознавание** на водомерах читает показание точно примерно в 3 случаях из 4, поэтому бот всегда показывает
  цифры на проверку. Для света, газа и тепла точность не измерена.
- **ФГИС «Аршин»** доступен только с российских IP, лимит 2 запроса в секунду. Поверитель передаёт сведения
  до 40 рабочих дней, поэтому «нет записи» не значит «не поверен». Заводской номер уникален только внутри типа
  прибора — при совпадении бот спрашивает, какой прибор ваш.
- **Смоделированы** передача в УК, окно подачи, счета, оплата, запись на поверку и права собственника (см. выше).
- Бот работает только в личных диалогах; телефон принимается только российский.
- Уведомления уходят с 9:00 до 21:00 МСК, не чаще одного на пользователя примерно за 10 минут, каждое один раз.
- Мини-приложение само не меняет профиль и адреса: для этого открывает чат с ботом.
- SQLite рассчитан на один процесс: для MVP этого хватает, для роста нужна другая БД.

## Масштабирование

- **Не меняется при переносе в другой регион:** сценарий подачи, распознавание, проверка поверки (ФГИС —
  федеральный реестр), адреса (DaData покрывает всю Россию), бот и мини-приложение в MAX.
- **Меняется:** передача показаний — интеграция с УК, РСО или ГИС ЖКХ вместо модели; график приёма показаний
  по адресу вместо общего окна; начисления из биллинга; подтверждение прав по данным УК или ЕГРН.
  Точки расширения в коде — [docs/architecture.md](docs/architecture.md#как-расширять).
- **Технически:** webhook вместо long polling, PostgreSQL вместо SQLite; `recognizer` не хранит состояние
  и масштабируется копиями.
