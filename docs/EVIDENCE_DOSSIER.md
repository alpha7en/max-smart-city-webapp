## 1. Государственная инфраструктура ЖКХ в РФ: Единая система и законы

### 1.1. Есть ли единая государственная система?
**Да, единая государственная система существует — это ГИС ЖКХ (Государственная информационная система жилищно-коммунального хозяйства).**
- **Официальный портал**: [dom.gosuslugi.ru](https://dom.gosuslugi.ru)
- **Базовый федеральный закон**: Федеральный закон от 21.07.2014 № 209-ФЗ «О государственной информационной системе жилищно-коммунального хозяйства».
- **Кураторы и оператор**: Министерство строительства и ЖКХ РФ (Минстрой), Министерство цифрового развития РФ (Минцифры), оператор — АО «Оператор информационной системы» (АО «Оператор ИС»).
- **Обязанность размещения информации**: Согласно ст. 155, 161 ЖК РФ и 209-ФЗ, все управляющие компании (УК), товарищества собственников жилья (ТСЖ), жилищно-строительные кооперативы (ЖСК), ресурсоснабжающие организации (РСО), региональные операторы ТКО, фонды капитального ремонта и расчетные центры (ЕИРЦ/РИЦ) **юридически обязаны** размещать сведения о домах, лицевых счетах, приборах учета, тарифах, начислениях и фактах оплаты в ГИС ЖКХ. За неразмещение предусмотрена административная ответственность по ст. 13.19.1 и 13.19.2 КоАП РФ.

### 1.2. Мобильный интерфейс государства: Приложение «Госуслуги Дом»
- Запущено Минстроем РФ и Минцифры РФ на базе инфраструктуры ГИС ЖКХ (разработчик мобильной платформы — VK / АО «Оператор ИС»).
- Авторизация осуществляется строго через ЕСИА (Госуслуги).
- Приложение автоматически агрегирует объекты недвижимости собственника по данным Росреестра и ГИС ЖКХ.
- Функционал:
  1. Передача показаний всех зарегистрированных индивидуальных приборов учета (ИПУ);
  2. Оплата выставленных счетов без комиссии через СБП (Систему быстрых платежей);
  3. Подача заявок в управляющую компанию с фиксацией сроков ответа;
  4. Проведение онлайн-голосований на общих собраниях собственников (ОСС).

### 1.3. Единые государственные идентификаторы
В ГИС ЖКХ каждому объекту и субъекту присваиваются сквозные машиночитаемые идентификаторы:
1. **ЕЛС (Единый лицевой счет)** — 10-значный уникальный номер (например, `10АА000000`), идентифицирующий плательщика и жилое помещение на всей территории РФ.
2. **ИЖКУ (Идентификатор жилищно-коммунальной услуги)** — привязан к конкретному поставщику и услуге в рамках ЕЛС.
3. **Идентификатор ПД (Платежного документа)** — уникальный номер квитанции, выгруженной в ГИС ЖКХ.
4. **Номер ПУ (Прибора учета)** — уникальный идентификатор счетчика в реестре ГИС ЖКХ.

## 2. Куда идут данные со счетчиков (ИПУ) и как устроен пайплайн передачи

### 2.1. Правовой статус приборов учета (ИПУ)
Отношения по снятию и передаче показаний регулируются **Постановлением Правительства РФ от 06.05.2011 № 354** («О предоставлении коммунальных услуг собственникам и пользователям помещений в многоквартирных домах и жилых домов»).
- Период передачи: как правило, с 15 по 25 число каждого месяца (конкретные даты фиксируются договором управления или решением собрания).
- Что происходит, если показания не переданы:
  - Первые 3 месяца расчет производится исходя из **среднемесячного объема потребления** за последние 6 месяцев (п. 59 Правил № 354);
  - Начиная с 4-го месяца — по **нормативу потребления** с применением повышающего коэффициента 1.5 (п. 60 Правил № 354).

### 2.2. Поверка счетчиков: Интеграция с ФГИС «АРШИН»
- С 24 сентября 2020 года (в соответствии с Федеральным законом № 102-ФЗ «Об обеспечении единства измерений») бумажные свидетельства о поверке не имеют юридической силы.
- Единственным законным подтверждением поверки является **электронная запись во ФГИС «АРШИН»** (реестр Росстандарта, `fgis.gost.ru`).
- Поверитель обязан внести данные во ФГИС «АРШИН» в течение 40 рабочих дней.
- Биллинговые системы УК/РСО и ГИС ЖКХ синхронизируют даты межповерочного интервала (МПИ) с ФГИС «АРШИН». Если срок поверки истек, счетчик автоматически блокируется в биллинге, и показания не принимаются.

### 2.3. Четыре схемы маршрутизации показаний

#### Схема А: Управление через УК/ТСЖ (традиционная модель)
```text
[Потребитель]
     │ (фото / ручной ввод)
     ▼
[Мобильное приложение / Личный кабинет УК]
     │
     ▼
[Биллинг УК (1С:ЖКХ / Инфокрафт / Стек-ЖКХ)]
     │
     ├──> Расчет начислений по формулам ПП РФ № 354
     │
     ▼ (экспорт через SOAP API hcs-device-meterings)
[ГИС ЖКХ]
```
Потребитель передает данные в УК (или уполномоченный расчетный центр). УК производит расчет и обязана выгрузить показания в ГИС ЖКХ.

#### Схема Б: Прямые договоры с РСО (Федеральный закон № 59-ФЗ / ст. 157.2 ЖК РФ)
При прямых договорах УК исключена из цепочки расчетов за коммунальные ресурсы.
Потребитель передает показания **каждому поставщику отдельно**:
- Холодная вода и водоотведение ➔ МУП «Водоканал»
- Горячая вода и отопление ➔ ПАО «МОЭК» / ПАО «Т Плюс» / Теплосеть
- Электроэнергия ➔ АО «Мосэнергосбыт» / ПСК / Энергосбыт
- Природный газ ➔ ООО «Газпром межрегионгаз»

#### Схема В: Единое окно через «Госуслуги Дом» / ГИС ЖКХ
```text
[Потребитель]
     │ (считывание камерой / ввод)
     ▼
[Мобильное приложение «Госуслуги Дом»]
     │
     ▼ (API платформы ГИС ЖКХ)
[ГИС ЖКХ: Сервис hcs-device-meterings]
     │
     ├──> Маршрутизация по ИЖКУ поставщику Холодной воды (Водоканал)
     ├──> Маршрутизация по ИЖКУ поставщику Электроэнергии (Энергосбыт)
     └──> Маршрутизация по ИЖКУ поставщику Горячей воды (Теплосеть)
```
ГИС ЖКХ сама знает, какая организация является Исполнителем коммунальной услуги (ИКУ) по каждому счетчику в квартире, и маршрутизирует данные в учетные системы соответствующих организаций.

#### Схема Г: Региональный оператор расчетов (Москва: mos.ru / Мособласть: МосОблЕИРЦ / СПб: ЕИРЦ СПб)
В мегаполисах действуют мощные региональные информационные системы (например, АСУ ЕИРЦ г. Москвы, mos.ru). Житель передает показания через mos.ru / «Госуслуги Москвы». Региональный биллинг производит начисления, формирует ЕПД и по интеграционным шлюзам передает данные в РСО и выгружает в федеральную ГИС ЖКХ.

### 2.4. Технические протоколы ГИС ЖКХ: SOAP API и СМЭВ 3
Для автоматического приема показаний ГИС ЖКХ предоставляет SOAP Web-сервисы:
- **WSDL-сервис**: `hcs-device-meterings` (сервис приборов учета и показаний);
- **Ключевой метод импорта**: `importMeteringDeviceValues` — пакетная загрузка текущих показаний счетчиков;
- **Ключевой метод экспорта**: `exportMeteringDeviceHistory` — получение истории показаний и номеров счетчиков по ЕЛС;
- **Требования безопасности**: Взаимодействие осуществляется либо через СМЭВ 3 (Система межведомственного электронного взаимодействия), либо через прямой защищенный TLS-канал с использованием квалифицированной электронной подписи (КЭП) по ГОСТ Р 34.10-2012.

## 3. Движение денег: Кому идет оплата с платежкой (ЕПД) и без нее

### 3.1. Сценарий 1: Есть единая платежка (Единый платежный документ — ЕПД)
В квитанции указан один расчетный счет и общая сумма к оплате.
- Получателем платежа выступает **ЕИРЦ / РИЦ (Единый информационно-расчетный центр)** либо уполномоченный расчетный банк.
- Потребитель совершает один платеж (картой, через СБП или по QR-коду).
- Деньги поступают на специальный банковский счет платежного агента.

### 3.2. Сценарий 2: Платежки нет (или прямые договоры без единого ЕИРЦ)
- Потребитель получает от 3 до 6 раздельных квитанций в почтовый ящик или личные кабинеты:
  1. Квитанция от УК — за «Содержание и текущий ремонт жилья», лифт, домофон, ОДН;
  2. Квитанция от Водоканала — за ХВС и водоотведение;
  3. Квитанция от Теплосети — за ГВС и отопление;
  4. Квитанция от Энергосбыта — за электроэнергию;
  5. Квитанция от Фонда капремонта (ФКР) — взнос на капитальный ремонт;
  6. Квитанция от Регионального оператора по обращению с ТКО — за вывоз мусора.
- Оплата по каждой квитанции перечисляется **отдельным банковским переводом** напрямую на расчетный счет соответствующей организации (счета коммерческих юрлиц `40702...` или спецсчет капремонта `40803...`).

## 4. Специальный банковский счет 40821 и механизм расщепления платежей (103-ФЗ)

### 4.1. Федеральный закон № 103-ФЗ и режим счета 40821
Федеральный закон от 03.06.2009 № 103-ФЗ «О деятельности по приему платежей физических лиц, осуществляемой платежными агентами» регулирует деятельность посредников при приеме коммунальных платежей.

**Балансовый счет 40821 («Специальный банковский счет платежного агента»):**
1. **Целевое назначение**: Предназначен исключительно для приема наличных и безналичных платежей от граждан за услуги третьих лиц и последующего расчета с поставщиками.
2. **Иммунитет от взысканий**: Денежные средства на счете 40821 **не являются собственностью платежного агента (ЕИРЦ/УК)**. На них не может быть обращено взыскание по долгам самого агента, их нельзя арестовать по налоговым претензиям к агенту или списать в рамках его банкротства.
3. **Закрытый перечень операций**:
   - Разрешено: зачисление платежей физлиц, перечисление средств поставщикам услуг (РСО, РО ТКО, ФКР, УК) и списание комиссии/вознаграждения агента на его собственный расчетный счет 40702.
   - Запрещено: оплата зарплат, аренды офиса, хозяйственных расходов или иных произвольных переводов.

### 4.2. Механизм банковского расщепления (Сплит-платежи)
Когда житель оплачивает ЕПД (например, 7 000 рублей) через банк (Сбер, Т-Банк, ВТБ) или терминал:
```text
                       [Житель: Оплата 7 000 руб.]
                                    │
                                    ▼
       [Спецсчет 40821 Платежного агента / Расщепляющий банк]
                                    │
     ┌──────────────┬───────────────┼──────────────┬──────────────┐
     │ 1 200 руб.   │ 2 100 руб.    │ 900 руб.     │ 600 руб.     │ 2 200 руб.
     ▼              ▼               ▼              ▼              ▼
[МУП Водоканал]  [ПАО МОЭК]    [Мосэнергосбыт]  [РО ТКО]     [УК (Содержание)]
(ХВС/Канализ.)   (Отопление/ГВС)  (Электроэнергия) (Вывоз мусора) (Текущий ремонт)
```
Расщепление осуществляется автоматически банком (например, расчетным сервисом Сбера или ВТБ) или биллингом ЕИРЦ в течение 1–3 операционных дней на основании **реестра начислений** по каждой услуге.

## 5. Как банки и сервисы сканируют платежки: ГОСТ Р 56042-2014 и OCR без QR-кода

### 5.1. Сканирование квитанции по QR-коду (ГОСТ Р 56042-2014)
Почти 100% современных квитанций ЖКХ в РФ содержат QR-код, сформированный по **ГОСТ Р 56042-2014** («Двумерные символы штрихового кода для осуществления платежей физических лиц»).

#### Формат строки данных:
- Служебный заголовок: `ST00011` (кодировка Windows-1251) или `ST00012` (кодировка UTF-8).
- Разделитель: `|`.
- Обязательные теги:
  - `Name` — Наименование получателя (УК / РСО / ЕИРЦ);
  - `PersonalAcc` — 20-значный расчетный счет получателя (например, `40702810...` или `40821810...`);
  - `BankName` — Наименование банка получателя;
  - `BIC` — 9-значный БИК банка (начинается на `04...`);
  - `CorrespAcc` — 20-значный корсчет банка в ЦБ РФ (начинается на `30101810...`).
- Специфические теги ЖКХ:
  - `Sum` — Сумма к оплате **в копейках** (например, `Sum=543020` означает 5430 руб. 20 коп.);
  - `PayeeINN` — ИНН получателя (10 цифр);
  - `KPP` — КПП получателя (9 цифр);
  - `PersAcc` — Номер лицевого счета абонента;
  - `PaymPeriod` — Расчетный период в формате `ММГГГГ` (например, `082026`);
  - `PayerAddress` — Адрес плательщика;
  - `TechCode` — Код услуги (01 — ЖКУ, 02 — газ, 03 — электроэнергия, 04 — вода).

#### Реальный пример строки QR-кода:
```text
ST00012|Name=ООО "УК ДОМ-СЕРВИС"|PersonalAcc=40702810438000012345|BankName=ПАО СБЕРБАНК|BIC=044525225|CorrespAcc=30101810400000000225|PayeeINN=7701987654|KPP=770101001|Sum=642050|Purpose=Оплата ЖКУ за 08.2026 ЛС 99887766|PersAcc=99887766|PaymPeriod=082026|PayerAddress=г. Москва, ул. Арбат, д. 12, кв. 5|LastName=Смирнов|FirstName=Дмитрий|MiddleName=Игоревич|TechCode=01
```

#### Алгоритм валидации на клиенте:
1. Декодирование QR-кода и проверка сигнатуры `ST0001`;
2. Проверка корректности БИК (сопоставление с базой БИК ЦБ РФ);
3. Проверка контрольного ключа расчетного счета: 9-й символ 20-значного счета вычисляется по специальному взвешенному алгоритму умножения на весовые коэффициенты `[7, 1, 3, 7, 1, 3...]` по модулю 10 с учетом трех последних цифр БИК. Если ключ не сходится — QR-код поврежден или сфальсифицирован;
4. Отрисовка формы в приложении с автозаполнением всех реквизитов.

### 5.2. Сканирование квитанции БЕЗ QR-кода (Computer Vision / OCR)
Если QR-код помят, залит водой или отсутствует (старая форма квитанции в регионах), ведущие банки и сервисы применяют оптическое распознавание символов (OCR) и интеллектуальное извлечение сущностей (Key Information Extraction — KIE).

#### Реализация в банках:
- **Т-Банк (Тинькофф)** и **ВТБ**: используют технологию российской компании **Smart Engines** (продукт **Smart Code Engine / Smart Document Engine**).
  - Работает **локально на процессоре смартфона (on-device)** через легковесные скомпилированные C++ / WebAssembly / Neural Engine модули;
  - Время обработки кадра: **менее 0.1 секунды**;
  - Не требует отправки фото на удаленный сервер (полное соответствие 152-ФЗ «О персональных данных»);
  - Алгоритм в реальном времени детектирует в кадре блоки текста, находит якорные ключевые слова («ИНН», «КПП», «БИК», «Р/сч», «Получатель», «К оплате») и валидирует найденные цепочки цифр по банковским алгоритмам контрольных сумм.
- **Content AI** (бывший ABBYY в РФ), **Dbrain**, **Yandex Vision**:
  - Серверные решения. Фотография квитанции загружается на бэкенд, где нейросетевые модели (LayoutLM, Donut, TrOCR) анализируют верстку документа, выделяют таблицу начислений, извлекают реквизиты получателя и возвращают структурированный JSON.

## 6. Как Сбер, ВТБ и другие игроки распознают счетчики по фото (AI Deep Dive)

### 6.1. Внедрение в СберБанк Онлайн (Счетчики воды)
- **Официальный запуск**: Официально представлен Центром искусственного интеллекта (ЦИИ) блока «Сервисы» Сбера (март 2024 / 2025 г.).
- **Заявленная точность**: **97%**.
- **Типы приборов**: Индивидуальные приборы учета горячей (ГВС) и холодной (ХВС) воды большинства российских и зарубежных производителей (Valtec, Itelma, Бетар, Метер, Декаст, Норма и др.).
- **Пользовательский путь**:
  1. Пользователь заходит в «СберБанк Онлайн» ➔ «Платежи» ➔ «Дом» / «ЖКХ»;
  2. Выбирает поставщика или адрес;
  3. В карточке счетчика нажимает значок камеры («Сфотографировать счетчик»);
  4. Делает фото встроенной камерой или прикрепляет снимок из галереи (например, пересланный арендатором или пожилым родственником через мессенджер);
  5. Нейросеть распознает цифры, заполняет поле ввода;
  6. Пользователь визуально сверяет цифры и нажимает «Передать показания».

### 6.2. Внедрение в ВТБ Онлайн (Счетчики электроэнергии)
- **Технологический партнер**: **Smart Engines**.
- **Специфика**: Сканирование счетчиков электроэнергии (в интеграции с АО «Мосэнергосбыт»).
- **Особенности**:
  - Распознавание работает прямо в «живом» видеопотоке камеры смартфона за 0.1 секунды;
  - Поддерживает однотарифные и многотарифные приборы (Т1 — пик/день, Т2 — ночь, Т3 — полупик);
  - Распознает как старые роликовые механизмы, так и современные LCD-экраны;
  - Работает локально на мобильном устройстве без передачи видеопотока на сервер банка.

### 6.3. «Электронный дом» (Москва) и «Госуслуги Дом»
- В приложении «Электронный дом» (Правительство Москвы, ДИТ) и «Госуслуги Дом» (Минстрой / VK) также реализован функционал оптического считывания показаний счетчиков воды с помощью камеры телефона с последующей возможностью ручной корректировки.

### 6.4. Нейросетевая архитектура пайплайна распознавания счетчика (ML Pipeline)
Реализация Сбера (на базе PyTorch / TorchOk) и классические state-of-the-art архитектуры делятся на 4 ключевых этапа:

```text
[Фото счетчика]
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. ДЕТЕКЦИЯ И ВЫРАВНИВАНИЕ (Detection & Alignment)          │
│ - Модель: YOLOv8-nano / MobileNetV4                         │
│ - Находит корпус счетчика и bounding box циферблата         │
│ - Spatial Transformer / Homography выравнивает перспективу  │
└─────────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. СЕГМЕНТАЦИЯ ЦИФЕРБЛАТА (Dial Zone Segmentation)          │
│ - Находит полосу счетных роликов (Digit Strip)              │
│ - КРИТИЧЕСКИ ВАЖНО: отделяет Черную зону (целые кубометры)  │
│   от Красной зоны (дробная часть / литры)                   │
└─────────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. РАСПОЗНАВАНИЕ ЦИФР (Digit OCR / Roll Transition)          │
│ - Модель: CNN + CTC Loss или классификатор разрядов         │
│ - Обработка краевого случая «полуоборота» (Half-turn roll): │
│   когда ролик застрял между цифрами (например, между 4 и 5) │
│ - Определение класса с максимальной уверенностью            │
└─────────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. БИЗНЕС-ВАЛИДАЦИЯ (Sanity Check / Anti-Hallucination)      │
│ - Проверка правила: V_текущее >= V_предыдущее               │
│ - Проверка дельты: (V_тек - V_пред) <= Порог_расхода (50 м³)│
│ - Если проверка не пройдена -> подсветка желтым / запрос OK │
└─────────────────────────────────────────────────────────────┘
```

#### Главная сложность и «подводный камень» в счетчиках воды:
У механических счетчиков воды 8 роликов:
- **Первые 5 роликов (черные)** — целые кубические метры ($м^3$). Именно их требуют передавать УК и расчетные центры.
- **Последние 3 ролика (красные)** — литры (тысячные доли $м^3$).
Если нейросеть неопытного разработчика распознает все 8 цифр подряд без разделения по цветам, пользователь вместо 145 кубов передаст показание 145 823 куба, что вызовет гигантское ошибочное начисление в сотни тысяч рублей! Полноценные решения Сбера и Smart Engines строго классифицируют цветовую принадлежность разрядов.

## 7. Рекомендуемая архитектура решения для хакатона

Для победы на хакатоне проект должен не просто «распознавать цифры с картинки», а решать сквозную бизнес-проблему жителя и города: **«Снял фото ➔ проверил ➔ данные ушли в биллинг ➔ начисление оплачено без комиссии»**.

### Архитектура MVP хакатон-сервиса:
```text
                         ПОЛЬЗОВАТЕЛЬСКИЙ СЛОЙ
 ┌──────────────────────────────────────────────────────────────────┐
 │  Telegram WebApp / Мобильный PWA / Flutter Client                │
 │  - Интерфейс камеры с рамкой прицеливания и фонариком            │
 │  - Клиентский препроцессинг (сжатие, ориентация EXIF)            │
 └────────────────────────────────┬─────────────────────────────────┘
                                  │ POST /api/v1/meter/scan
                                  ▼
                         БЭКЕНД СЕРВИСА (FastAPI)
 ┌──────────────────────────────────────────────────────────────────┐
 │ 1. ML-сервис инференса (ONNX Runtime / TensorRT):                │
 │    - Детектор циферблата (YOLOv8n)                               │
 │    - Детектор цветовой зоны (Mask R-CNN / Color thresholding)    │
 │    - OCR цифр с вычислением уверенности (Confidence Score)       │
 │                                                                  │
 │ 2. Модуль профиля квартиры:                                      │
 │    - Хранение ЕЛС, номеров заводских счетчиков ХВС/ГВС           │
 │    - Хранение предыдущих показаний (История потребления)         │
 │                                                                  │
 │ 3. Модуль интеграции и отправки показаний:                       │
 │    - Генерация XML/JSON пакета для SOAP API hcs-device-meterings │
 │    - Коннекторы к API 1C:ЖКХ / Telegram-бот УК / Email-шлюз      │
 │                                                                  │
 │ 4. Модуль мгновенной оплаты:                                     │
 │    - Генератор QR-кода по ГОСТ Р 56042-2014 с реквизитами УК     │
 │    - Кнопка оплаты через СБП (Deeplink в мобильный банк)         │
 └──────────────────────────────────────────────────────────────────┘
```

### Киллер-фичи для жюри хакатона:
1. **Защита от ошибки с литрами**: визуальная подсветка распознанных кубометров зеленым цветом, а отсеченных литров — серым/красным.
2. **Валидация по историческому расходу**: сравнение с прошлым месяцем. Если расход аномальный (например, 0 кубов при проживании 3 человек или 80 кубов при обычном расходе 8) — предупреждение о возможной утечке или ошибке распознавания.
3. **Автоматическая сверка с ФГИС «АРШИН»**: по введенному номеру счетчика сервис проверяет дату следующей поверки и напоминает жителю за 2 месяца до окончания срока.
4. **Бесшовная оплата через ГОСТ-QR / СБП**: житель видит сумму к оплате и может нажать одну кнопку для перехода в приложение любого банка.
