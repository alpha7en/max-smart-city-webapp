# Живая проверка в MAX

Чек-лист для человека и для скилла `live-scenario`. Бот проверяется в настоящем MAX (`web.max.ru` или приложение),
облачные агенты до MAX не достают. Баг — тупик, молчание, обрезанная кнопка, видимые `**`, служебные теги или
сырые URL. Текст, который отличается от ожидания, но передаёт тот же смысл, — не баг.

Где смотреть: **L** — `docker compose logs -f app` (ищи `trace=`, `MAX API`, `polling error`);
**DB** — `sqlite3 data/bot.db` (`sessions`, `users`, `user_addresses`, `meters`, `readings`, `photos`);
**F** — файлы `data/photos/`; **DT** — DevTools браузера (фрейм мини-приложения).
**[НЕ ПРОВЕРЕНО]** — поведение MAX, которое живьём ещё не подтверждали: результат записать явно.

## 4. Мини-приложение

Мини-приложение из MAX открывается с `https://maxsmartcity.ru` и ходит в API этого сервера, а не в локальный
бот: полностью этот раздел проверяется только после деплоя.

| # | Сделать в MAX | Должно произойти | При сбое |
|---|---|---|---|
| 4.1 | Кнопка «Мини-приложение» в меню | открывается внутри MAX, а не в браузере | кнопка должна быть `open_app` с username бота |
| 4.2 | initData | DT Console (фрейм): `WebApp.initData` непустая; Network: `/api/me` → 200, не 401 | строку проверить `python -m tools.live_smoke --check-init-data '<строка>'` (саму строку не публиковать) |
| 4.3 | start_param | кнопка «Smoke 5» (`live_smoke --yes --keep`) → `WebApp.initDataUnsafe.start_param === "smoke_1"` | `--check-init-data` показывает `start_param` |
| 4.4 | Открыть незарегистрированным аккаунтом | «Продолжите регистрацию в чате с ботом» | `/api/me` → `registered: false` |
