## 2. Компоненты системы

### 2.1. Чат-бот MAX (`app/bot/`)
- Работает по официальному протоколу MAX Bot API на домене `https://platform-api2.max.ru`;
- Авторизация через заголовок `Authorization: <token>`;
- Поддерживает получение событий через **Long Polling** (`GET /updates`) и **Webhook** (`POST /subscriptions`);
- Обрабатывает входящие фотографии счетчиков, извлекает вложения (`type: image`), формирует интерактивные inline-клавиатуры (`inline_keyboard`) с кнопками типов `link`, `callback`, `open_app`.

### 2.2. Мини-приложение MAX (`app/static/`)
- Легковесный адаптивный SPA-интерфейс, стилизованный под дизайн-токены **MAX UI**;
- Подключает официальную библиотеку **MAX Bridge** (`https://st.max.ru/js/max-web-app.js`);
- Использует нативные возможности мессенджера:
  - `window.WebApp.openCodeReader(true)` — аппаратное сканирование QR-кодов камерой устройства;
  - `window.WebApp.BackButton` — нативное управление историей переходов;
  - `window.WebApp.HapticFeedback` — тактильный отклик устройства на действия пользователя;
  - `window.WebApp.enableClosingConfirmation()` — защита от случайного закрытия при заполнении форм.

### 2.3. Доменные службы (`app/services/`)
1. **`MeterService`**:
   - Реализует алгоритм отсечения дробных разрядов литров (красные ролики), предотвращая ошибку передачи данных в 1000 раз;
   - Контролирует монотонность показаний (`текущее >= предыдущее`);
   - Рассчитывает среднее потребление и выявляет аномальные всплески (>25 м³).
2. **`ArshinService`**:
   - Сверяет заводской номер счетчика с реестром ФГИС «АРШИН» Росстандарта;
   - Генерирует юридически мотивированный «Зеленый Щит Безопасности», защищающий жителей от мошенников.
3. **`GostQrService`**:
   - Парсит платежные строки формата `ST00012` по ГОСТ Р 56042-2014;
   - Проверяет контрольный ключ расчетного счета Банка России (модуль 10 с весовыми коэффициентами 7, 1, 3);
   - Выполняет расчет сплит-платежа по 103-ФЗ и 59-ФЗ на специальный счет 40821.
4. **`NightFlowService`**:
   - Анализирует почасовую телеметрию общедомового счетчика (ОДПУ) в ночное окно (02:30 – 04:30);
   - Вычисляет вероятность скрытых ночных утечек;
   - Проводит экспресс-диагностику неисправности клапана бачка унитаза («Тест салфетки»).
5. **`TicketService`**:
   - Управляет заявками в аварийно-диспетчерскую службу по Постановлению Правительства РФ № 40 от 26.01.2026 г.;
   - Назначает жесткие SLA: 30 минут на локализацию аварии, 24 часа на устранение срочных проблем.
6. **`GuestAccessService`**:
   - Генерирует временные криптографически стойкие гостевые токены для арендаторов;
   - Формирует диплинки вида `https://max.ru/<bot>?startapp=<token>`.

## 3. Описание заглушек (Mocks / Stubs)

В соответствии с требованиями регламента хакатона, все внешние компоненты, требующие аппаратных ускорителей нейросетей или закрытых контуров межведомственного взаимодействия, реализованы в виде чистых, воспроизводимых стабов с явной маркировкой:

1. **`AiVisionService` [ЗАГЛУШКА / AI VISION STUB]**:
   - Эмулирует работу двухстадийного пайплайна: детекция циферблата (YOLOv8) + распознавание символов барабана (TorchOk / EasyOCR) + выравнивание проекции (гомография).
   - Возвращает координаты bounding box'ов, раздельные значения черных и красных барабанов, распознанный серийный номер и флаг `is_mock=True` с явным текстом дисклеймера в API.
2. **Внешний шлюз ГИС ЖКХ [ЗАГЛУШКА]**:
   - Эмулирует SOAP WSDL вызов `importMeteringDeviceValues` сервиса `hcs-device-meterings`, возвращая статус успешной регистрации в реестре ЕЛС.
3. **Банковский шлюз СБП [ЗАГЛУШКА]**:
   - Эмулирует авторизацию платежа в Системе быстрых платежей и расщепление средств на спецсчет платежного агента 40821.
