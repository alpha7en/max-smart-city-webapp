# Архитектура сервиса для хакатона: Автоматическая передача показаний и оплата

## 1. Сквозной пользовательский сценарий (User Journey)
1. Житель открывает Telegram WebApp (или веб-сервис);
2. Направляет камеру на счетчик воды или электроэнергии;
3. Сервис мгновенно:
   - Выделяет рамку циферблата;
   - Отсекает красные ролики (литры), оставляя только целые кубометры;
   - Сверяет с прошлым месяцем (Sanity Check: исключает аномалии);
4. На экране появляется интерактивная карточка: «ХВС: 145 м³ (расход за месяц: +4 м³ = 236 руб.)»;
5. Пользователь нажимает одну кнопку «Отправить и оплатить»:
   - Показания отправляются в биллинг УК / ГИС ЖКХ;
   - Генерируется ГОСТ-QR код или прямая ссылка на оплату через СБП в любимом банке.

## 3. Киллер-фичи для защиты перед жюри
1. **Решение «проблемы красных роликов»**: наглядно покажите жюри, как обычный OCR ошибается в 1000 раз, путая литры с кубами, и как ваш сервис надежно фильтрует цветовую шкалу.
2. **Проверка межповерочного интервала (МПИ)**: сервис проверяет номер прибора по открытому API ФГИС «АРШИН» и предупреждает о приближении поверки.
3. **Бесшовная генерация ГОСТ-QR для оплаты в любом банке**: решение не привязано к одному банку — сформированный QR-код считывается Сбером, Т-Банком, ВТБ, Альфой без комиссии.
