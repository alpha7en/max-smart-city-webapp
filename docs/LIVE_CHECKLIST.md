# Живая проверка бота в MAX

Для человека и для Claude (скилл `live-scenario`). Ожидания взяты из сценария владельца и SPEC.
Если текст в боте отличается, но смысл тот же, это не баг. Баг — тупик, молчание, обрезанная кнопка,
видимые `**`, служебные теги или сырые URL.
Где смотреть: **L** — `docker compose logs -f app` (ищи `trace=`, `MAX API`, `polling error`);
**DB** — `sqlite3 data/bot.db` (sessions, users, user_addresses, meters, readings, photos);
**F** — файлы `data/photos/`; **DT** — DevTools браузера (фрейм мини-приложения, Console/Network).
Шаги с пометкой **[НЕ ПРОВЕРЕНО]** живьём ещё не проверял никто. Результат записать явно: да или нет, и что пришло.

## 4. Мини-приложение
Мини-приложение из MAX ходит в `MINIAPP_API_BASE` (сервер), а не в локальный бот. Полная проверка возможна только после деплоя.

| # | Сделать в MAX | Должно произойти | При сбое |
|---|---|---|---|
| 4.1 | Кнопка «Мини-приложение» в меню | открывается внутри MAX, а не вкладкой браузера | кнопка должна быть open_app с username бота |
| 4.2 | **[НЕ ПРОВЕРЕНО]** initData | DT Console (контекст фрейма): `WebApp.initData` непустая; Network: `/api/me` → 200, не 401 | скопировать строку → `python -m tools.live_smoke --check-init-data '<строка>'` |
| 4.3 | **[НЕ ПРОВЕРЕНО]** start_param | открыть кнопку «Smoke 5» (`live_smoke --yes --keep`) → `WebApp.initDataUnsafe.start_param === "smoke_1"` | `--check-init-data` покажет start_param |
| 4.4 | Незарегистрированный аккаунт | баннер «Продолжите регистрацию в чате» | web/static/app.js, /api/me registered=false |
| 4.5 | Подать показание в мини-приложении | экран результата, в чат пришло подтверждение | L; DB readings.source = miniapp |
| 4.6 | Бэкенд не задан / недоступен | пустой `MINIAPP_API_BASE`: «Сервер мини-приложения не подключён» + «Вернуться в чат»; сервер не отвечает: «Нет связи с сервером». Без демо-данных | CORS: MINIAPP_ORIGINS; скилл `miniapp-tunnel` |
