## 2. Компоненты системы

### 2.1. Bot Service (`src/bot.py`)
- **Протокол связи**: Официальный MAX Bot API (`https://platform-api2.max.ru`).
- **Транспорт**: 
  - Режим разработки и хакатона: **Long Polling** (`GET /updates`), не требующий внешнего «белого» IP или ngrok.
  - Продакшн-режим: **Webhook** (`POST /subscriptions`).
- **Авторизация**: Заголовок `Authorization: <BOT_TOKEN>`.
- **Защита секретов**: Токен считывается из переменных окружения (`.env` / `token.env`).

### 2.2. WebApp Mini-App (`src/webapp/`)
- **Фреймворк**: Стандартные веб-технологии HTML5 / CSS3 / ES-Next (Vanilla / React), оптимизированные под требования MAX UI.
- **Интеграция с платформой**: Библиотека нативного моста `https://st.max.ru/js/max-web-app.js`.
- **Используемые методы `window.WebApp`**:
  - `initData`: стартовые параметры для криптографической валидации пользователя через HMAC-SHA256.
  - `openCodeReader(fileSelect)`: встроенный высокоточный сканер QR-кодов.
  - `HapticFeedback.impactOccurred('medium')` / `notificationOccurred('success')`: тактильный отклик при успешном распознавании.
  - `BackButton.show()` / `onClick()`: бесшовная навигация внутри мессенджера.
  - `DeviceStorage` / `SecureStorage`: кэширование адресов и лицевых счетов на устройстве.

### 2.3. CV Meter Pipeline (`src/api/cv_pipeline.py`)
- **Текущий статус**: Полнофункциональная эмуляционная заглушка (`[ЗАГЛУШКА CV / MOCK]`), отражающая логику боевой модели:
  - Автоматическая классификация типа счетчика (ХВС / ГВС / Однотарифный свет / Двухтарифный Т1-Т2).
  - Разделение барабанных роликов: целая часть ($m^3$ или кВт·ч) и дробная часть (красные ролики / десятые доли).
  - Выделение серийного номера прибора учета.
  - Проверка аномалий (превышение среднемесячного расхода > 300%, отрицательная дельта).
- **План продакшн-реализации**:
  - Легковесный YOLOv8-nano для детекции счетчика и табло.
  - Perspective Transform (гомография по 4 точкам) для устранения съемки под углом.
  - Segmentation / Digit OCR (PaddleOCR / TorchOk) с жестким разделением по цветовой маске HSV (черные ролики vs красные).

### 2.4. Внешние интеграции
1. **ФГИС «АРШИН» (Росстандарт)**:
   - Эндпоинт: `https://fgis.gost.ru/fundmetrology/eapi/vri`.
   - Назначение: мгновенная проверка даты следующей поверки по заводскому номеру прибора.
2. **ГИС ЖКХ / УК**:
   - Приказ Минстроя РФ об информационном взаимодействии через ГИС ЖКХ и мессенджер MAX.
   - Передача показаний в формате XML/JSON в биллинговые системы управляющих компаний (1С:ЖКХ, Стек, Инфокрафт).

## 3. Модель безопасности

1. **Защита персональных данных (152-ФЗ)**:
   - В чат-боте не хранятся паспортные данные и полные реквизиты собственности.
   - Идентификация пользователя происходит по `user.id` мессенджера MAX и криптографическому хешу `initData`.
2. **Иммунитет платежей (103-ФЗ)**:
   - Оплата квитанций направляется строго на спецсчета управляющих организаций (балансовый счет **40821**), защищенные от безакцептного списания судебными приставами и кредиторами.
3. **Гостевой доступ для арендаторов**:
   - Арендодатель формирует одноразовый/постоянный гостевой токен привязки к квартире без передачи прав доступа к ЕСИА/Госуслугам.

## 4. Контейнеризация и запуск (Docker)

В соответствии с требованиями хакатона («Умный город.pdf», стр. 9):
- Сборка и запуск выполняются одной командой: `docker compose up --build -d`.
- Время сборки образа не превышает **5 минут** благодаря использованию легковесного базового образа `python:3.11-slim`.
- Спецификация портов: порт `8000` (бэкенд API и статика мини-приложения).
