## 3. Проверка граничных условий и Edge Cases

1. **Граничный случай: пользователь ввел все 8 цифр с циферблата (142789 вместо 142.0):**
   - *Поведение:* `MeterService.filter_red_rollers` автоматически распознает переданные 8 цифр и отсекает 3 младших красных разряда (литры). Начисление формируется корректно. Ошибка предотвращена.
2. **Граничный случай: ввод показаний меньше предыдущих (счетчик «скручен» или опечатка):**
   - *Поведение:* Система возвращает ошибку монотонности с понятным предупреждением: «Новое значение меньше предыдущего (142.0)». Данные не записываются.
3. **Граничный случай: некорректный расчетный счет или БИК банка:**
   - *Поведение:* Алгоритм модуля 10 с весовыми коэффициентами Банка России фиксирует невалидность контрольного разряда и выставляет бейдж ошибки, предотвращая уход денег на неверные счета.
4. **Граничный случай: обрыв связи с реестром Росстандарта:**
   - *Поведение:* Включается кэширующий fallback-слой, не блокирующий пользователя, и возвращается информационный статус из локального реестра.

## 4. Проверка через Docker (Воспроизводимость в 1 команду)

Решение подготовлена для развертывания одной командой:
```bash
docker compose up --build
```
- **Время сборки образа:** менее **30 секунд** (при лимите регламента до 5 минут);
- **Проверка работоспособности контейнера:** встроенный `HEALTHCHECK` с интервалом 15 секунд (`curl -f http://localhost:8080/api/health`);
- **Поддержка переменных окружения:** безопасный шаблон `.env.example`.
